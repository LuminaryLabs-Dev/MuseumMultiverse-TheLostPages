# Lost Pages Docs

This folder contains human-facing project documentation for Museum Multiverse: Lost Pages.

## Documents

- `../goal.md` owns the active twelve-pass mission and pass status.
- `CURRENT-STATE.md` is the canonical dated snapshot of implemented,
  validated, unverified, historical, and proposed state.
- `DOCUMENTATION-MAP.md` assigns one canonical owner to each documentation
  concern.
- `SIMULATOR-PLAYER-PROOF.md` defines simulator-first rules proof and separate
  Playwright player-view acceptance.
- `FINAL-PRODUCT-GOAL.md` defines the final shared flow and all eight measurable
  page contracts.
- `SIMPLE-GAMEPLAY-CONTRACT.md` defines the exact shared phases, commands,
  one-hero selector, recovery, save, replay, and eight-page verb extensions.
- `ARCHITECTURE-SKILL-MAP.md` assigns the minimal product-facing domain,
  adapter, coordinate, performance, and existing-skill ownership.
- `GOAL-MATRIX.md` maps every shared and page outcome to current evidence, gap,
  dependency, next action, validation, and status.
- `../CHANGELOG.md` reconstructs the product and architecture history from all
  Git commits.
- `project-overview.md` explains what Lost Pages is.
- `eight-pages-qr-structure.md` explains the eight page QR model.
- `repository-map.md` explains the repo layout.
- `prototype-workflow.md` explains how prototype work should happen.
- `nexusengine-dependencies.md` explains the current NexusEngine boundary.
- `deployment-and-discord.md` explains Pages deployment and deploy chat output.
- `feedback-loop.md` explains feedback handling.
- `agent-operating-model.md` explains the long-running agent system.

## Truth Rule

When documents disagree, check live source and proof first, then
`CURRENT-STATE.md`. Use `../goal.md` for desired direction. Historical and
provisional records must not be described as current implementation.
