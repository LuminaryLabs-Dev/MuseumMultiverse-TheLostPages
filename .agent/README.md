## Preserved Interview Rules

The rules below describe how the closed discovery interview was conducted.
They do not authorize new repeated-question batches.

- Do not implement application or runtime changes during discovery.
- Ask exactly one material question per assistant output.
- Give two to four numbered choices.
- Record each issued question and every direct user answer.
- Revise the idea and synthesized contracts when an answer changes direction.
- After five unanswered questions, visibly record evidence-based provisional
  self-answers for that five-question batch, then ask one new question.
- Direct user answers always override provisional self-answers.

## Organization Rules

- Store every authoritative question, decision, evidence block, intention, and
  authority state once at the path named by its index.
- Never renumber stable question or batch ids.
- Closed ledger shards are immutable; live records stay in `current` files.
- Hash indexes are refreshed whenever their owned current record changes.
- Exact duplicates may be removed only after verifying the canonical copy and
  recording a redirect.
- Keep runtime source, execution attempts, and legacy operations outside this
  discovery tree.
- Do not promote provisional discovery into root `memory.md`; that file holds
  concise accepted lasting repo purpose, architecture, and conventions only.
