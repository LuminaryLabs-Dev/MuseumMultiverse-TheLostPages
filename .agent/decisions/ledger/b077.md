# Picture-Frame Platformer Decision Ledger

## Batch 077

Questions 381-385 received no user selection. These choices define the
mixed-media runtime construction, material catalog, route package graph,
landmark presentation authority, and deterministic art-review surface. They
remain open to direct user override and grant no asset generation, runtime
implementation, rights-sensitive reuse, push, or deployment authority.

### 381. Mixed-Media Runtime Construction

Selection: use one hybrid modular asset kit. Lightweight layered or
shallow-extruded paper modules and approved atlases visualize critical course
elements over independent semantic volumes. Compact custom glTF modules own
hero landmarks, signature mechanisms, rewards, and selected dimensional props;
JR remains the canonical hybrid cutout rig. Shared material families carry
route-specific palettes and motifs, key art renders from the same accepted
scenes, and device tiers remove only noncritical detail.

Rationale:

- The current generic descriptors and placeholder images do not establish a
  finished art-production method.
- Hybrid construction preserves handcrafted depth and route identity within
  phone budgets.
- Independent semantics prevent visible meshes and pixels from becoming
  gameplay authority.

### 382. Material and Texture Catalog

Selection: use one versioned two-level material catalog with a compact shared
paper, ink, cloth, wood, gilt, cue-mask, and bounded-shader core plus one small
palette-and-motif atlas or array layer per route. Stable bindings pin revision,
hash, provenance, rights, color space, channels, UV contract, tiers, display
role, and fallback. Critical non-color meaning remains in dedicated masks,
shallow geometry, labels, or equivalent text; runtime and key art use the same
accepted revisions.

Rationale:

- A shared core avoids arbitrary per-mesh conventions without flattening route
  identity.
- Prepackaged tiers preserve critical cues while reducing only resolution and
  decorative microdetail.
- Textures and shaders remain presentation rather than collision, matching,
  progress, or eligibility inputs.

### 383. Route Asset Packaging

Selection: publish one content-addressed package graph beneath an atomic
all-eight release root. It references a small shared core, one tiered package
per route, one tiny journey-motif and reward package, and one separate
source-bound key-art catalog. Manifests pin identities, hashes, byte sizes,
dependencies, tiers, provenance, rights, criticality, and fallbacks. Each
route preflights its exact required set before reveal; only declared neutral
dressing may stream later.

Rationale:

- Phones should not download every full world to enter one route.
- Page 08 needs journey motifs without loading seven prior landmarks.
- An atomic root preserves all-eight coherence, rollback, quarantine, and
  reproducible key-art identity.

### 384. Landmark Animation and VFX Authority

Selection: use one closed typed presentation catalog driven only by stable
semantic states and event ids. A small shared intent vocabulary maps to
route-original clips, poses, materials, particles, and static frames with
pinned interruption, tier, accessibility, and fallback contracts. Milestone
state persists before presentation. Animation callbacks, final poses,
simulation, particles, elapsed render time, and effect success never change
gameplay state.

Rationale:

- Current loose effect names do not provide a deterministic animation
  contract.
- Typed intent preserves route-specific expression and accessible parity.
- Persist-first presentation makes interruptions safe and keeps the domain
  authoritative.

### 385. Deterministic Visual Review Surface

Selection: use one repo-owned read-only Visual Review Lab that loads the exact
candidate manifest and accepted semantic snapshot. Reviewers can reproduce
routes, states, physical host profiles, viewing envelopes, device tiers,
accessibility modes, key-art cameras, diagnostics, and forced fallback cases,
then export immutable hash-bound evidence. The lab may flag problems but cannot
edit candidates, accept rights, waive gates, promote, deploy, or replace
browser, phone, physical-AR, and human-view proof.

Rationale:

- Artists and reviewers need one shared runtime-faithful surface rather than
  disconnected beauty renders.
- Disclosed diagnostics make placement, bindings, budgets, and fallbacks
  inspectable without cluttering the normal player-facing view.
- Read-only evidence preserves the separate O5 promotion boundary.
