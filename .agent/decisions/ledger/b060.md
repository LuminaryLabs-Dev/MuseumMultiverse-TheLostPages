## Batch 060

Questions 296-300 received no user reply. These selections define Page 02's
glyph-to-route conversion, glyph language, manipulation, preview, and portal
finish. They remain open to direct user override and grant no implementation
or external-action authority.

### 296. Page 02 Glyph-to-Path Conversion

Selection: bind allowed states of three stable glyph sockets to named edges in
one authored route graph. Teach one causal bridge, then preview one of two valid
two-glyph arrangements. All inputs emit revision-bound
`glyph.align(glyphId,socketId,recipeRevision)` intent. `Lock Route` pins the
accepted graph, and preview, folds, collision, accessible description, Run,
snapshot, replay, and portal eligibility consume its stable ids and hash.

Rationale:

- Alignment becomes the platformer planning rule instead of a separate counter.
- One authoritative graph prevents visual and collision drift.
- Invalid or stale intent cannot silently mutate the route.

### 297. Page 02 Glyph Roles

Selection: give the three glyphs stable `Bridge`, `Step`, and `Gate` meanings.
Bridge connects a span, Step selects an authored upper or lower landing
pattern, and Gate locks the traversable route and wakes the portal after the
run. Each owns a distinct silhouette, label, non-color cue, semantic id, and
accessible description; Page 08 may recall the same learned meanings.

Rationale:

- Stable roles make cause and effect teachable.
- Multimodal identities avoid color-only puzzle logic.
- Finale reuse can test recognition rather than invent a second glyph language.

### 298. Page 02 Glyph Manipulation

Selection: constrain each glyph to a shallow frame-local guide between its
resting cradle and compatible fixed sockets. Drag-to-socket,
select-glyph/select-socket, keyboard or D-pad, switch scanning, and ordered text
submit the same command and preview. Only a valid release changes accepted
state; invalid placement returns to the prior state.

Rationale:

- Bounded movement retains tactile 3D placement without six-degree ambiguity.
- Equivalent semantic inputs preserve accessibility and deterministic replay.
- Invalid actions cannot alter route truth.

### 299. Page 02 Route Preview

Selection: apply every accepted glyph state to the semantic graph immediately
during Plan, then animate only that exact bounded fold while JR waits.
Highlight the affected edge, update the ordered route, show dormant collision
silhouettes, and enable `Lock Route` only for a traversable graph. Reduced
motion uses a labeled static swap.

Rationale:

- Immediate feedback exposes the relationship between glyph and course.
- Planning remains safe and reversible before traversal.
- Semantic state leads presentation rather than following renderer animation.

### 300. Page 02 Portal Finish

Selection: after `Lock Route`, use the shared countdown and traverse the actual
glyph-built bridge and landing pattern. Failure returns to the last short
checkpoint with the graph unchanged. A 300-millisecond grounded-center portal
dwell exposes explicit `Enter Portal`; completion and
`breathing-frame-mark` persist before presentation and return.

Rationale:

- The player must prove the route they constructed.
- Shared checkpoint and portal rules preserve all-eight consistency.
- Persist-before-presentation keeps completion and reward delivery idempotent.
