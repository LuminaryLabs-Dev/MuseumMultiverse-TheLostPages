### Key-Art Subflow

- The graph remains fixed at five orchestrators, five middle skills, and fifteen
  atomic skills. O4 extends M4 rather than creating another owner.
- O3 emits one immutable read-only `key-art-source-packet` per route. O4
  validates it and emits one source-hash-bound `key-art-candidate-packet`; O5
  emits an applicability verdict bound to both hashes. O4 cannot write semantic
  changes upstream.
- M4 coordinates staging and catalog assembly. A11-A12 own visual identity,
  renderer bindings, manifests, folios, fallbacks, and source-bound candidates.
  A13-A15 prove budgets, physical-family cameras and crops, semantic
  truthfulness, accessibility, QR/print entry, failure behavior, and human view.
- Semantic changes revise the source and stale its transitive dependents.
  Art-only changes revise the candidate and rerun only affected proofs. Shared
  changes fan out to exact dependents, and any required stale input closes the
  all-eight join.
- Production promotion requires an exact-hash O5 verdict and one coherent
  content-addressed all-eight catalog root. Route candidates may preview
  independently, but production swaps one pointer atomically and retains the
  prior accepted root for rollback. A runtime art failure invokes only that
  route's accessible fallback.

### Deterministic Runtime Profile

- O3 owns one authoritative 60 Hz semantic clock. The host processes no more
  than four catch-up ticks per render, never drops or merges ticks, and adds a
  visible typed performance pause when backlog exceeds the bounded window.
- Every route pins one versioned normalized museum-family collision profile
  with inset grounded and airborne JR bodies, expanded landing tops, inset
  hazards, swept tests, fixed epsilon, and explicit visible assistance-only
  variants. Renderer and device geometry remain non-authoritative.
- Commands use one closed versioned envelope bound to route, run, recipe
  revision, stable id, monotonic sequence, target tick, allowlisted type,
  schema, and semantic payload. Admission produces deterministic accepted,
  duplicate, or typed-rejection results without silent repair.
- Pauses persist as a snapshot- and replay-preserved set of stable typed records
  with owner, entered tick, legal recovery commands, clear condition, and
  accessible label. Only owner-scoped or declared domain acknowledgments clear
  a reason, and simulation resumes only when the set is empty.
- Semantic snapshots persist one ordered event outbox bound to exact run,
  revision, id, tick, sequence, type, schema, payload hash, consumer, and
  acknowledgment policy. Same-id retries use idempotent consumers; gating
  pauses remain until exact acknowledgment or explicit bounded recovery; restore
  replays unacknowledged events in order.
